## 2. Постановка задачи и контекст

### 1. Предметная область и задача:
Проект решает задачу **регрессии** — прогнозирование непрерывной величины (цены автомобиля в USD) на основе набора разнородных признаков. Потенциальными пользователями такого сервиса могут быть:
- Площадки по продаже автомобилей (для автоматической оценки объявлений).
- Страховые компании (для быстрой оценки стоимости застрахованного имущества).
- Индивидуальные покупатели и продавцы, желающие оценить адекватность цены на рынке.

Сценарий использования: пользователь отправляет структурированный JSON-запрос со спецификациями автомобиля и получает оценку стоимости в реальном времени.

### 2. Формулировка задачи в терминах ML:
- **Входные данные ($X$):** 11 признаков автомобиля, включая категориальные (марка, модель, тип кузова, трансмиссия, цвет кузова и салона, штат регистрации, комплектация) и числовые (год выпуска, пробег в милях, оценка состояния по 5-балльной шкале).
- **Целевая переменная ($y$):** Числовое значение цены продажи (`sellingprice`).
- **Требования к решению:** Высокая скорость инференса (время ответа < 100 мс), устойчивость к пропускам в данных, а также интерпретируемость результатов.

### 3. Целевые метрики качества:
Для оценки качества модели выбраны две метрики:
1. **MAE (Mean Absolute Error):** Средняя абсолютная ошибка. Показывает среднее отклонение предсказания от реальной цены в долларах, что легко интерпретируется бизнесом.
2. **$R^2$ (Коэффициент детерминации):** Показывает долю дисперсии зависимой переменной, объясняемую моделью. Значение ближе к 1 свидетельствует о высоком качестве соответствия модели данным.

## 3. Данные

### 1. Источник данных:
В проекте используется открытый датасет **Vehicle Sales** с платформы Kaggle, содержащий информацию о транзакциях купли-продажи автомобилей на аукционах США. 

### 2. Структура данных:
Обучающая выборка содержит информацию о характеристиках транспортных средств:
- Числовые признаки: `year` (год выпуска), `condition` (состояние от 1.0 до 5.0), `odometer` (пробег).
- Категориальные признаки: `make` (производитель), `model` (модель), `trim` (версия комплектации), `body` (тип кузова), `transmission` (тип КПП), `state` (штат), `color` (цвет кузова), `interior` (цвет салона).
- Целевой признак: `sellingprice` (цена продажи в USD).

### 3. Предобработка и EDA:
Разведочный анализ данных (EDA) показал наличие пропусков в категориальных и числовых полях. В ходе предобработки выполнены следующие шаги:
- Строки с пропущенным целевым признаком `sellingprice` удалялись из выборки.
- Пропуски в категориальных переменных заполнялись значением `'Unknown'` с приведением к строковому типу.
- Пропуски в числовых переменных заполнялись медианными значениями по соответствующим колонкам для предотвращения искажения распределения.
- Выделен демонстрационный срез данных (`data/sample_car_prices.csv`) объемом 100 строк для быстрой проверки работоспособности сервиса и тестов без загрузки тяжелого датасета.

Основные шаги EDA и построения базовой модели зафиксированы в Jupyter-ноутбуке: `notebooks/exp01_eda_baseline.ipynb`.

## 4. Модели и подходы

### 1. Базовая модель (Baseline):
В качестве базового решения была выбрана модель градиентного бустинга `CatBoostRegressor`. Данный выбор обусловлен способностью алгоритма эффективно обрабатывать большое количество категориальных признаков с высокой кардинальностью (например, марки и модели машин) «из коробки» без необходимости сложного кодирования (One-Hot или Target Encoding) вручную.

При базовых настройках (500 итераций, шаг обучения 0.1) модель показала высокую обобщающую способность, в связи с чем дальнейший уход в сторону нейросетевых архитектур в рамках текущего спринта был признан нецелесообразным.

## 5. Экспериментальный протокол и результаты

### 1. Экспериментальный протокол:
Для проведения экспериментов использовалась подвыборка в 100 000 строк. Данные разделялись на обучающую и валидационную выборки в соотношении 80/20 со случайным разбиением (параметр `random_state=42` для воспроизводимости). Метрики рассчитывались на отложенной тестовой выборке.

### 2. Результаты экспериментов:

| Конфигурация модели | Описание | MAE ($) | $R^2$ | Комментарий |
|---|---|---|---|---|
| **CatBoost (Baseline)** | Параметры по умолчанию, 100k строк | 1548.70 | 0.9154 | Финальная модель, оптимальный баланс точности и скорости |

### 3. Выбор финальной модели:
Финальной моделью выбрана `CatBoostRegressor`. Достигнутый коэффициент детерминации $R^2 \approx 0.915$ указывает на то, что модель успешно выявила закономерности ценообразования. Средняя ошибка в $1548 является приемлемой для практического использования в задачах предварительной оценки автотранспорта.

## 6. Архитектура решения и сервис

### 1. Архитектура пайплайна:
Взаимодействие компонентов системы устроено следующим образом:
1. Модуль `src/data/loader.py` считывает конфигурации из `configs/config.yaml`, загружает сырой `.csv`, проводит чистку данных и заполнение пропусков.
2. Скрипт `src/models/train.py` обучает модель на подготовленных данных и сохраняет сериализованные веса модели в бинарный файл `artifacts/catboost_model.cbm`.
3. Веб-сервис `src/service/app.py` на базе `FastAPI` при запуске инициализирует менеджер контекста `lifespan`, загружает веса модели в оперативную память и ожидает POST-запросы на эндпоинт `/predict`.

### 2. API и эндпоинты:
Реализовано два эндпоинта:
- `GET /` — проверка состояния здоровья сервиса (health-check). Возвращает текущий статус системы.
- `POST /predict` — инференс модели. Принимает JSON-объект с характеристиками машины, проверяет типы данных через валидацию Pydantic v2 и возвращает предсказанную стоимость в формате:
  ```json
  {
    "predicted_price_usd": 12264.45
  }
