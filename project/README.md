# Итоговый проект по курсу «Инженерия Искусственного Интеллекта»

В этой папке находится итоговый мини-проект по курсу.  
Проект демонстрирует применение методов и инструментов инженерии ИИ: работу с табличными данными, обучение модели машинного обучения, обертку в REST API сервис, версионирование данных с помощью DVC и контейнеризацию в Docker.

## 2. Структура проекта

Проект организован в следующей структуре:

- `requirements.txt` – зависимости проекта.
- `pytest.ini` – файл конфигурации путей для запуска тестов.
- `Dockerfile` – скрипт сборки Docker-образа сервиса.
- `report.md` – отчёт по проекту (постановка задачи, данные, эксперименты, результаты).
- `self-checklist.md` – чеклист самопроверки проекта перед сдачей.
- `notebooks/` – экспериментальные ноутбуки:
  - `exp01_eda_baseline.ipynb` – первичный разведочный анализ данных (EDA) и построение базовой модели.
- `src/` – основной код проекта:
  - `data/loader.py` – модуль для загрузки, очистки данных и заполнения пропущенных значений.
  - `models/train.py` – скрипт для запуска пайплайна обучения модели и сохранения весов.
  - `service/app.py` – исходный код веб-сервиса на базе FastAPI.
- `data/` – демонстрационные/учебные данные:
  - `raw/car_prices.csv.dvc` – метаданные оригинального датасета (отслеживается DVC).
  - `sample_car_prices.csv` – урезанная демонстрационная выборка (100 строк) для быстрой проверки.
- `configs/` – конфигурационные файлы:
  - `config.yaml` – все настройки проекта (пути к данным, гиперпараметры модели, параметры API).
  - `.env.example` – шаблон переменных окружения для деплоя.
- `tests/` – автоматические тесты:
  - `test_data_loading.py` – тесты корректности загрузки данных (sanity-checks).
  - `test_service.py` – интеграционные тесты эндпоинтов API.
- `artifacts/` – папка для хранения сохраненной модели:
  - `catboost_model.cbm` – сериализованные веса обученной модели CatBoost.

Если структура проекта отличается от базовой, опишите это здесь.

## 3. Требования и установка

### 3.1. Требования

- Python `>= 3.10`.
- Установленный Docker (для запуска контейнера).
- DVC (Data Version Control) для работы с датасетом.

### 3.2. Установка окружения

```bash
# Перейти в папку проекта
cd project

# Создать виртуальное окружение (опционально, но рекомендуется)
python -m venv .venv

# Активировать окружение:
# Windows:
.venv\Scripts\activate
# Linux / macOS:
source .venv/bin/activate

# Установить зависимости
pip install --upgrade pip
pip install -r requirements.txt
```

## 4. Как запустить проект

Все настройки проекта (пути, параметры модели, метаданные API) считываются динамически из файла configs/config.yaml.

### 4.1. Запуск обучения модели

```bash
cd project
python -m src.models.train
```

### 4.2. Запуск сервиса (API/веб-интерфейс)

```bash
cd project
python -m uvicorn src.service.app:app --reload
```

Или, если используется Docker:

```bash
cd project

# Сборка образа
docker build -t car-price-predictor .

# Запуск контейнера с пробросом порта 8000
docker run -p 8000:8000 car-price-predictor
```

### 4.3 Эндпоинты API и проверка работы

- **`GET /`** - Health-check (проверка работоспособности сервиса).
- **`GET /docs`** - Интерактивная документация Swagger UI.
- **`POST /predict`** - Эндпоинт для отправки характеристик машины и получения предсказанной цены.

Пример POST-запроса через утилиту `curl`:

```bash
curl -X 'POST' \
  'http://127.0.0.1:8000/predict' \
  -H 'accept: application/json' \
  -H 'Content-Type: application/json' \
  -d '{
  "year": 2015,
  "make": "Ford",
  "model": "Fusion",
  "trim": "SE",
  "body": "Sedan",
  "transmission": "automatic",
  "state": "ca",
  "condition": 4.5,
  "odometer": 60000,
  "color": "black",
  "interior": "black"
}'
```

Ожидаемый ответ от модели:
```json
{
  "predicted_price_usd": 12264.45
}
```

## 6. Тесты (если есть)

В проекте настроено автоматическое тестирование на базе библиотеки `pytest`.
Реализовано два типа тестов:
1. Sanity-checks (`tests/test_data_loading.py`): Проверка структуры данных, корректности заполнения пропущенных значений (NaN) и состава колонок после обработки загрузчиком.
2. Интеграционные тесты (`tests/test_service.py`): Проверка работоспособности API, корректности кодов ответов (200 OK) и структуры JSON-ответов инференса модели.

Запуск тестов из папки `project/`:

```bash
cd project
pytest
```

## 8. Ограничения и дальнейшая работа

Текущие ограничения прототипа:

- Модель обучена на подвыборке в 100 000 строк для оптимизации времени обучения в рамках суточного спринта.
- Нет глубокого извлечения признаков (Feature Engineering) из текстовых полей, содержащих комплектации автомобилей.
- В API отсутствует модуль авторизации пользователей.

Направления развития проекта:

- Обучение модели на полном объеме данных (500k+ строк).
- Создание простого веб-интерфейса на базе Streamlit для интерактивного выбора параметров машины на веб-странице.
- Интеграция системы трекинга экспериментов и логирования MLflow.
